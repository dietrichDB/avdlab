# Lab playbook — AVD 6.4 + ANTA 1.10 on containerlab / ACT / Proxmox

Condensed, opinionated recipe distilled from `01`–`03`. Defaults chosen for fast iteration; every choice is
reversible. Platform priority: **containerlab + cEOS-lab** (primary), ACT digital twin (when we need vEOS/CloudEOS or
CVP), vEOS-lab on Proxmox (when we need VM-level behaviour).

## 0. Repo skeleton (one directory per lab)

```text
<lab>/
├── ansible.cfg                # [defaults] inventory=inventory.yml  duplicate_dict_key=error
├── inventory.yml              # groups: FABRIC > DC1 > {DC1_SPINES, DC1_L3_LEAVES, DC1_L2_LEAVES}; NETWORK_SERVICES, CONNECTED_ENDPOINTS
├── group_vars/
│   ├── FABRIC.yml             # connectivity vars + fabric-wide design vars (fabric_name: FABRIC)
│   ├── DC1.yml                # mgmt_gateway, management_eapi
│   ├── DC1_SPINES.yml / DC1_L3_LEAVES.yml / DC1_L2_LEAVES.yml   # type: + <type>: {defaults, node_groups, nodes}
│   ├── NETWORK_SERVICES.yml   # tenants:
│   └── CONNECTED_ENDPOINTS.yml# servers:, port_profiles:
├── playbooks/ build.yml  deploy.yml  validate.yml
├── clab/                      # generated by avd2clab.py (topology.clab.yml, *.EosIntfMapping.json, hosts/*.sh)
├── anta/                      # user_catalogs/ (ours), avd_catalogs/ + reports/ (generated)
├── intended/                  # generated: structured_configs/, configs/
└── documentation/             # generated: fabric/, devices/
```

Tooling: `pip install "pyavd[ansible]==6.4.0" anta==1.10.0 && ansible-galaxy collection install arista.avd:==6.4.0`;
containerlab ≥ 0.60 (kind `arista_ceos`); cEOS-lab image imported as `arista/ceos:<ver>` (`docker import cEOS64-lab-<ver>.tar.xz arista/ceos:<ver>`).

## 1. Decisions baked into the templates

| Decision | Value | Why |
|---|---|---|
| Design | eBGP underlay + eBGP EVPN overlay, spines = route servers, MLAG leaf pairs | AVD default path; matches production designs we RFP |
| `platform` | `cEOSLab` (containerlab) / `vEOS-lab` (Proxmox/ACT) | selects the virtual `platform_settings` entry (no wait-install, no storm-control, no hardware ANTA tests) |
| Management interface | keep AVD default **Management1**, bind `EosIntfMapping.json` (`eth0→Management1`) | same config works on cEOS, vEOS and ACT; avoids the `custom_platform_settings` override |
| eAPI | `management_eapi: {enabled: true}` + `mgmt_ip` on every node | mandatory in 6.x for deploy and ANTA |
| Users | `aaa_settings.local_users`: `admin` (no_password) + `arista/arista` (`cleartext_password`) | matches example bootstrap; ANTA/Ansible use `arista` |
| Startup | containerlab `startup-config: ../intended/configs/<host>.cfg` | no bootstrap configs, no first deploy; `enforce-startup-config: true` re-applies on redeploy |
| MTU | leave `p2p_uplinks_mtu` 9214 on containerlab (veth OK); set `1500` on Proxmox/EVE unless bridges are jumbo | vEOS README advice |
| BFD | `bfd_multihop: {interval: 1200, min_rx: 1200, multiplier: 3}` on VM labs | CPU |
| Endpoints | `linux` (alpine) containers from `connected_endpoints` | lightweight; cEOS "server" only when we need LACP/VLAN behaviour |
| Validation | `anta_runner` with `avd_catalogs_extra_fabric_validation: true`, skip `VerifyNTP`, `VerifyReloadCause` in containers | NTP unreachable; container reload cause |

## 3. Playbooks

```yaml
# playbooks/build.yml
- hosts: FABRIC
  gather_facts: false
  tasks:
    - import_role: {name: arista.avd.eos_designs}
    - import_role: {name: arista.avd.eos_cli_config_gen}

# playbooks/deploy.yml   (only needed after the first boot; first boot uses startup-config)
- hosts: FABRIC
  gather_facts: false
  tasks:
    - import_role: {name: arista.avd.eos_config_deploy_eapi}

# playbooks/validate.yml
- hosts: FABRIC
  connection: local
  gather_facts: false
  tasks:
    - import_role: {name: arista.avd.anta_runner}
      vars:
        avd_catalogs_extra_fabric_validation: true
        user_catalogs_enabled: true
        anta_report_exclude_statuses: [success, skipped]
        avd_catalogs_filters:
          - skip_tests: [VerifyNTP, VerifyReloadCause]
```

## 4. Order of operations (containerlab)

```bash
ansible-playbook playbooks/build.yml                                   # 1. render intended/ + documentation/
python3 avd2clab.py --root . --fabric FABRIC --image arista/ceos:4.34.2F # 2. clab/topology.clab.yml from topology.csv
sudo containerlab deploy -t clab/topology.clab.yml --reconfigure        # 3. boot with intended configs as startup-config
sleep 120                                                               #    cEOS needs 1–3 min; wait for `show bgp summary` to converge
ansible-playbook playbooks/validate.yml                                 # 4. ANTA via anta_runner -> anta/reports/anta_report.md
# iterate:
vi group_vars/...; ansible-playbook playbooks/build.yml && ansible-playbook playbooks/deploy.yml --check --diff && ansible-playbook playbooks/deploy.yml
# interface change (new links)? -> re-run avd2clab.py and `containerlab deploy --reconfigure` (re-applies startup-config)
sudo containerlab destroy -t clab/topology.clab.yml --cleanup
```

`avd2clab.py` (stored next to this doc) reads `documentation/fabric/<FABRIC>-topology.csv` + `intended/structured_configs/*.yml`,
de-duplicates links, writes one `EosIntfMapping.json` per switch (`eth0→<rendered mgmt intf>`, `ethN→EthernetN`), makes
endpoints `linux` containers with `ethN` in order of appearance, and sets `mgmt-ipv4` = AVD `mgmt_ip`. It was verified to
reproduce the shipped `single-dc-l3ls` clab topology link-for-link.

Direct ANTA (outside Ansible), reusing AVD's per-device catalogs:

```bash
anta get from-ansible --ansible-inventory inventory.yml --ansible-group FABRIC -o anta/inventory.yml   # uses ansible_host only
export ANTA_USERNAME=arista ANTA_PASSWORD=arista ANTA_INVENTORY=anta/inventory.yml
anta nrfu -c anta/avd_catalogs/dc1-leaf1a.json --catalog-format json -d dc1-leaf1a table
anta nrfu -c anta/user_catalogs/lab.yml --hide success md-report --md-output anta/reports/user.md --expand
```
Inventory `name:` must equal the AVD hostname, because AVD tags every generated test with the hostname.

## 5. ACT (Arista Cloud Test) path — digital twin

```bash
ansible-playbook playbooks/build.yml -e avd_digital_twin_mode=true \
   -e output_dir_name=digital_twin/intended -e documentation_dir_name=digital_twin/documentation
# upload digital_twin/documentation/fabric/FABRIC-topology.yml to ACT; nodes boot vEOS with mgmt ip_addr from mgmt_ip
```
Set once in `group_vars/FABRIC.yml`:
```yaml
digital_twin:
  environment: act
  fabric: {act_os_version: "4.33.1F", act_username: cvpadmin, act_password: "cvp123!", act_ensure_eapi_access: true}
```
Twin mode rewrites hardware platforms to `vEOS-lab` (via `platform_settings[].digital_twin.platform`), forces
`Management1`, refuses `mgmt_ip: dhcp`, and adds `metadata.digital_twin` to each structured config. Node overrides:
`<type>.nodes[].digital_twin: {act_os_version, mgmt_ip, mgmt_gateway, act_internet_access}`. Then run the normal
`deploy.yml`/`validate.yml` against the ACT eAPI endpoints (use the twin's `intended/configs`).

## 6. vEOS-lab on Proxmox path

- VM: first NIC = `Management1` (bridge to mgmt VLAN), NICs 2..N = `Ethernet1..N-1` in order; `vEOS64-lab-<ver>.qcow2`
  as disk + `Aboot-veos-serial-*.iso` for serial console; 2 vCPU / 4 GB is enough for small fabrics.
- Day-0: paste a bootstrap (`hostname`, `username arista … secret`, `vrf instance MGMT`, `interface Management1 / vrf MGMT / ip address`,
  `ip route vrf MGMT 0.0.0.0/0 <gw>`, `management api http-commands / protocol https / no shutdown / vrf MGMT / no shutdown`), `write`.
- group_vars deltas: `platform: vEOS-lab`, `p2p_uplinks_mtu: 1500` (unless bridges carry 9214), `bfd_multihop: {interval: 1200, min_rx: 1200, multiplier: 3}`.
- Then `build.yml` → `deploy.yml --check --diff` → `deploy.yml` → `validate.yml`. Same ANTA behaviour as cEOS (`hw_model` = `vEOS-lab`).

## 7. Checklist before asking "why doesn't it converge"

1. `ansible-playbook playbooks/build.yml` clean (no schema errors, no "EOS Config keys found at top level" warning)?
2. `intended/configs/<leaf>.cfg` has `management api http-commands`, `interface Management1 … ip address`, the `arista` user?
3. `docker exec -it dc1-leaf1a Cli -c "show interfaces status"` — Ethernet1..N present? If only `Ethernet0`, the `EosIntfMapping.json` bind is wrong/missing.
4. `show bgp summary` on a spine: underlay peers `Estab`, EVPN peers `Estab`? If `Active`: check `PL-LOOPBACKS-EVPN-OVERLAY` covers the pools (loopback pool /27 → `eq 32` entries), `bgp_as` per node_group, `uplink_ipv4_pool` big enough.
5. MLAG: `show mlag` → `Active`? Peer-link Port-Channel3 up, Vlan4094 up; both nodes in the same 2-node `node_group`; ids unique.
6. VXLAN: `show interfaces Vxlan1` source Loopback1; `show bgp evpn summary`; `show vxlan vni`.
7. ANTA report: hardware tests should be absent (not generated), `VerifyLLDPNeighbors` failing usually = wrong link in clab topology (re-run `avd2clab.py`).
8. Config replace fails on cEOS → a hardware-only command sneaked in: check `platform:` string is exactly `cEOSLab` and no `raw_eos_cli` uses hardware CLI.
